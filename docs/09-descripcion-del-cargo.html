09 · Descripción del cargo (JD)

Texto de referencia de la vacante a la que responde esta prueba técnica. Se reproduce sin alteraciones y se usa como entrada para verificar cobertura: qué exige el rol, qué demuestra hoy el repositorio y qué queda pendiente.

Este documento no implica vinculación laboral ni reproduce documentación interna del cliente. El JD es el texto de la convocatoria.

9.1 Texto original

TEXTO ORIGINAL DE LA VACANTE · USO DE REFERENCIA

AI CONTEXT DESARROLLADOR FULL STACK SENIOR JAVA (SPRING BOOT / WEBFLUX) + ANGULAR, CON AZURE Y MICROFRONTENDS

Remoto2,5 meses160 h/mes1 recurso8:00–17:00

Objetivo del rol

Modernizar y extender la plataforma del cliente de punta a punta: ejecutar el upgrade progresivo de Java y Spring Boot, construir APIs REST y reactivas integradas con servicios serverless y de mensajería en Azure, y estructurar la base de dos portales con arquitectura de microfrontends en Angular, dejando estándares que el equipo del cliente pueda seguir.

Responsabilidades principales

  • Planear y ejecutar el upgrade progresivo desde Spring Boot 2.3.x y Java 8 hacia versiones recientes, resolviendo incompatibilidades (javax a jakarta, Spring Security, dependencias) sin afectar la operación.
  • Desarrollar APIs RESTful con Spring (MVC y WebFlux), documentadas con Swagger/OpenAPI.
  • Implementar Azure Functions e integración por colas y eventos con Azure Service Bus y Event Grid; usar Azure Storage (Blob, Table) según el caso de uso, y MySQL como base relacional.
  • Diseñar y construir la base de los dos portales de microfrontends: shell/host, módulos remotos con Module Federation, dependencias compartidas y comunicación entre microfrontends.
  • Desarrollar aplicaciones y web components en Angular (15 o superior) con RxJS, maquetación responsive mobile first (Flexbox, SASS/LESS/CSS) y criterios de accesibilidad.
  • Desplegar los portales en Azure Static Web Apps y los servicios con Docker y pipelines de Azure DevOps.
  • Escribir pruebas unitarias con JUnit (backend) y Jest (frontend).
  • Definir y documentar lineamientos técnicos (patrones de diseño, SOLID, estructura de proyectos) y diagramas en Mermaid.
  • Revisar código y acompañar técnicamente al equipo del cliente.

Requisitos técnicos obligatorios

  • Lenguajes: Java (8, 11 y 17, con experiencia real migrando entre versiones), TypeScript y JavaScript moderno (APIs recientes del navegador y de Node.js).
  • Backend: Spring Boot (2.x y 3.x), Spring Web, Spring WebFlux (Project Reactor), APIs RESTful, Swagger/OpenAPI.
  • Frontend: Angular 15 o superior, RxJS, HTML5, CSS3, SASS, Flexbox, diseño responsive mobile first.
  • Microfrontends: Module Federation y web components.
  • Base de datos: MySQL.
  • Cloud: Azure Functions, Azure Service Bus, Azure Event Grid, Azure Storage Account (Blob, Table), Azure Static Web Apps.
  • DevOps / CI/CD: Docker, Azure DevOps (Repos, Pipelines).
  • Testing: JUnit, Jest.
  • Herramientas: Git (ramas, merge, rebase, resolución de conflictos), VS Code, Postman o Insomnia.
  • Prácticas: patrones de diseño, principios SOLID, programación funcional (lambdas) y reactiva.

Requisitos técnicos deseables

  • Java 25 y Spring Boot 4.
  • React y Stencil para microfrontends y web components.
  • Progressive Web Apps (PWA) y WebSockets.
  • LESS.
  • Accesibilidad web formal (WCAG 2.x).
  • Diagramación con Mermaid.
  • Herramientas de migración automatizada (por ejemplo, OpenRewrite).
  • Certificación Azure (AZ-204 o AZ-900).
  • Uso de asistentes de IA para refactorización, pruebas y documentación, con control humano.

Requisitos blandos

  • Autonomía alta: debe producir desde la primera semana por la corta duración del servicio.
  • Criterio técnico para tomar y sustentar decisiones de arquitectura ante el cliente.
  • Capacidad de priorizar entre frentes (migración, Azure y portales) con un solo recurso.
  • Comunicación clara y por escrito, propia de un trabajo remoto.
  • Documentación técnica de las decisiones y estándares definidos.

Experiencia mínima

  • Mínimo exigido: 5 años como desarrollador full stack.
  • Al menos 4 años en Java/Spring, incluida al menos una migración de versión de Spring Boot o Java.
  • Al menos 3 años en Angular.
  • Al menos un proyecto con microfrontends (Module Federation) y experiencia comprobable en Azure (Functions y Service Bus).

Formación, modalidad y condiciones

Formación: profesional, tecnólogo o estudiante de últimos semestres con experiencia sólida en ingeniería de sistemas o afines.

Modalidad: remoto. Horario de 8:00 a 17:00.

Duración: 2,5 meses. Dedicación: 160 horas/mes (tiempo completo). Cantidad de recursos: 1.

9.1.1 Comparativa del bloque Cloud

Cuadro de análisis, no forma parte del texto original. Contrasta las cinco tecnologías citadas con lo que la cuenta gratuita de Azure incluye hoy, y con el estado real en este repositorio.

Tecnología del JD ¿Free tier? Capacidad incluida Qué implica en la práctica Estado en el prototipo
Azure Functions (plan Consumption) Sí, permanente 1 000 000 de ejecuciones y 400 000 GB-s al mes Unas 33 000 ejecuciones al día sin coste Adaptador de notificación previsto; no hay código de Function
Azure Functions (plan Flex Consumption) Sí, permanente 250 000 ejecuciones y 100 000 GB-s al mes Menos ejecuciones que Consumption; útil si se quiere escala a cero por instancia Alternativa de plan, no usada

Dos costes que la columna «free tier» no revela: Functions necesita una cuenta de almacenamiento para su estado, que se factura aparte; y el crédito de 200 USD de la cuenta gratuita caduca a los 30 días, no a los 12 meses. Los servicios marcados «permanente» no vencen, pero tampoco cubren a sus dependencias.

9.4 Brechas declaradas

  1. La migración no se ejecutó sobre una aplicación real. Hay estrategia, reglas y compatibilidad documentadas; el laboratorio de código heredado y la receta de OpenRewrite están pendientes.
  2. El backend no compila todavía. Es un esqueleto avanzado; faltan servicios, migraciones y pruebas (ver documento 07).
  3. No hay frontend. Los dos portales, el shell y los remotos son diseño, no implementación.
  4. No hay despliegue en Azure. Existen adaptadores y decisiones, no recursos provisionados ni pipeline ejecutado.
  5. Cobertura de pruebas: cero. No se declara ninguna suite en verde.
  6. Table Storage se evaluó y se descartó porque el caso de uso no lo requiere; queda como decisión razonada, no como omisión.

9.5 Contexto para asistentes de IA

Bloque compacto para reutilizar al pedir ayuda a un asistente sobre este repositorio:

Proyecto: prueba técnica Bits Americas para Colsubsidio. Prototipo independiente, datos sintéticos.
Objetivo: modernización Java 8/Boot 2.3 -> Java 17/Boot 3.x, APIs REST + Reactor,
          Azure (Functions, Service Bus, Event Grid, Blob) y dos portales Angular con Module Federation.
Restricciones duras:
  - No afirmar integración con sistemas reales de Colsubsidio ni usar PII real.
  - Las reglas de negocio son de demostración; ninguna aprobación es oficial.
  - Ejecutable en local sin suscripción de Azure (adaptadores locales).
  - No reportar pruebas como exitosas sin ejecutarlas.
Fuente de verdad: docs/01..09 (alcance, FR, NFR, arquitectura, trazabilidad, plan, inventario, UC, JD).
Backend: co.com.bits.colsubsidio, módulos por funcionalidad, MVC + JPA, Reactor en streaming y mensajería.
Salida esperada: código compilable, pruebas ejecutadas, decisiones justificadas y documentación en español.

9.6 Uso en la entrevista

  • Minuto 0–2: el JD pide tres frentes con un solo recurso; el plan de 06 explica el orden y por qué.
  • Minuto 2–5: el flujo vertical de 08 (UC-03 → UC-13) demuestra integración, no piezas aisladas.
  • Minuto 5–8: 04 justifica decisiones incómodas: MVC con Reactor acotado, monolito modular, Module Federation con webpack.
  • Cierre: 9.3 y 9.4 muestran lo que falta sin maquillarlo; la honestidad sobre el estado es parte de la evaluación.
